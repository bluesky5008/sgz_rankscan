## 문제와 목적

공헌 랭킹 화면은 순위·세력명(유저명)·지역·동맹을 표시하지만 게임 밖으로 내보내는 기능이 없어 600명 분량을 옮겨 적으려면 수작업이 필요하다. 이 작업은 PC 클라이언트를 자동 제어하여 랭킹 목록을 스크롤하며 캡처하고, 이미지 인식으로 텍스트를 추출해 저장함으로써 랭킹 데이터의 보관·집계를 가능하게 한다.

## 대상과 시나리오

- 대상 사용자: 본인(로컬 PC에서 CLI를 직접 실행하는 단일 사용자).
- 주 시나리오: 클라이언트가 로그인된 메인 화면 상태에서 CLI를 실행하면, 도구가 `더 보기 → 랭킹 → 공헌 랭킹 탭`으로 이동한 뒤 목록을 위에서부터 스크롤하며 각 행을 캡처·인식·저장하고, 600위 도달 또는 목록 끝에서 멈춰 결과를 요약 보고한다. 처음 등장한 세력명·지역·동맹은 사용자가 라벨을 확정한다.

## 범위

### 포함

- 구동 시 대상 클라이언트 창 동적 탐지와 다중 후보 시 사용자 선택(sgz_statiz FR-08과 동일 절차)
- 메인 화면에서 공헌 랭킹 탭까지 자동 화면 이동(이미 공헌 랭킹 화면이면 이동 생략)
- 랭킹 목록의 스크롤 순회와 종료 판정(순위 상한 기본 600, 목록 끝)
- 행 단위 이미지 캡처(순위별 행 크롭 + 근거 전체 프레임)
- 각 행의 순위 번호 확정과 연속성 검증(누락·중복 검출)
- 세력명·지역·동맹의 텍스트 추출 — 템플릿 기반 안정 식별자 + OCR 제안 라벨 + 사용자 라벨 확정
- 실행(run) 단위 영속 저장과 CSV 내보내기
- 실행 요약 보고

### 제외

- 개인 랭킹·동맹 랭킹 탭, 타 서버(`본 서버` 드롭다운 변경)
- 화면에 표시되지 않는 값(공헌 점수 등)의 추출
- 통계 분석·시각화(저장 데이터로 추후 별도 작업)
- 클라이언트 자동 실행·로그인, 실행 종료 후 게임 화면 원상 복귀
- 게임 상태를 변경하는 조작(화면 이동·스크롤 외의 클릭)

## 기능 요구사항

| ID | 항목 | 내용 |
|---|---|---|
| FR-01 | 자동 화면 이동 | 메인 화면에서 `더 보기 → 랭킹 → 공헌 랭킹 탭` 순서로 이동해야 한다. 각 단계는 클릭 후 목표 화면 마커를 판정하고 나서 다음 단계로 진행해야 한다. 실행 시점에 이미 공헌 랭킹 화면이면 이동을 생략하고 진행해야 한다. |
| FR-02 | 목록 순회 | 공헌 랭킹 목록을 위에서부터 스크롤하며 화면에 완전히 표시된 행을 모두 처리해야 한다. `--max-rank`(기본 600)에 도달하거나 더 이상 스크롤되지 않으면 종료해야 한다. |
| FR-03 | 순위 확정 | 처리하는 각 행에 순위 번호를 확정해야 한다. 확정한 순위는 1부터 연속이어야 하며, 연속성이 깨지면(누락·중복) 그 사실을 기록하고 복구 또는 중단해야 한다(NFR-01). |
| FR-04 | 행 이미지 저장 | 행마다 행 크롭 이미지를 순위로 식별되는 파일명으로 저장하고, 근거가 된 스크롤 단계별 목록 영역 프레임을 함께 보관해야 한다(전체 프레임은 중단 시에만). |
| FR-05 | 텍스트 추출 | 각 행에서 세력명·지역·동맹 셀을 잘라 안정적 식별자(ID)로 저장해야 한다. 처음 등장한 셀은 새 ID를 발행하고 OCR 제안 라벨과 함께 `pending` 상태로 등록하며, 확정된 라벨은 이후 실행에서 자동 적용되어야 한다. 근거: [P-02 OCR 프로토타입](#가정과-미해결-질문) — 한자 접두·장식 프레임이 붙은 세력명은 OCR 단독으로 신뢰할 수 없다. |
| FR-06 | 실행 단위 저장 | 한 번의 실행(run)에서 추출한 행 레코드(순위, 세력명 ID, 지역 ID, 동맹 ID, 크롭 경로, 인식 상태)를 run에 귀속시켜 영속 저장해야 한다. 같은 run 안에서 같은 순위가 두 번 저장되어서는 안 되며, 서로 다른 run의 레코드는 모두 보존되어야 한다(주기 실행 이력). |
| FR-07 | 라벨 확정 | `pending` 식별자를 순회하며 크롭을 보여 주고 사용자가 라벨을 확정하는 절차를 제공해야 한다. 확정 라벨은 기존·이후 레코드 조회에 반영되어야 한다. |
| FR-08 | 실행 요약 | 실행 종료 시 처리 순위 범위, 저장 행 수, 인식 실패 수와 사유, 순위 연속성 이상, pending 식별자 수를 요약 보고해야 한다. |
| FR-09 | 창 선택 | 구동 시 제목(`삼국지-전략판`)으로 클라이언트 창 후보를 탐지해야 한다. 후보가 여럿이고 대화형이면 목록 표시·번호 선택·전면 확인(y/n)을 거치고, 하나면 자동 진행하며, `--hwnd` 지정 시 생략하고, 비대화형 다중 후보면 목록과 함께 거부(종료 코드 1)해야 한다. |
| FR-10 | CSV 내보내기 | 저장된 run 레코드를 UTF-8(BOM) CSV로 내보내야 한다. 행에는 run 식별, 순위, 세력명·지역·동맹의 라벨(미확정이면 `#ID(제안)` 표기)과 크롭 경로가 포함되어야 한다. |

## 비기능 요구사항

| ID | 항목 | 내용 |
|---|---|---|
| NFR-01 | 강건성 | 개별 행의 인식 실패가 전체 실행을 중단시켜서는 안 된다. 실패 행은 크롭과 함께 실패로 기록하고 다음 행으로 진행해야 한다. 단, 순위 연속성 상실(FR-03)은 데이터 무결성 문제이므로 복구 시도 후 실패하면 실행을 중단하고 그때까지의 결과를 보존해야 한다. |
| NFR-02 | 화면 대기 | 화면 전환·스크롤 대기는 고정 시간이 아니라 화면 상태 판정(템플릿 매칭·프레임 안정화) 기반이어야 하며, 상한 시간 초과 시 해당 단계를 실패로 처리해야 한다. |
| NFR-03 | 검증 가능성 | 모든 행 레코드는 근거 크롭 경로를 가져 사후 검증이 가능해야 한다. |
| NFR-04 | 환경 호환 | sgz_statiz와 동일한 클라이언트 환경(창 제목 `삼국지-전략판`, 클라이언트 2544×657)에서 동작해야 하며 다른 크기는 실행을 거부해야 한다. |
| NFR-05 | 백그라운드 동작 | 캡처와 입력은 창이 다른 창에 가려진 상태에서도 동작해야 한다(sgz_statiz와 동일: Windows Graphics Capture + PostMessage). |

## 제약과 의존성

- 실행 환경: Windows 11, 삼국지 전략판 PC 클라이언트(창 모드, 클라이언트 2544×657). 사실: 참고 이미지 창 2546×689와 2026-09-28 실기 스냅샷(창 0x206be, client 2544×657) 모두 sgz_statiz 캘리브레이션과 일치.
- 사실: 게임 클라이언트가 관리자 권한으로 실행 중이면(2026-09-28 실기 `elevated=True`) 입력 전달에 도구의 승격이 필요하다. 캡처만은 승격 불필요.
- 클라이언트 제어·캡처·인식·저장 기술은 [sgz_statiz](file:///C:/src/git/sgz_statiz)의 구현을 재사용한다. 재사용 범위는 설계에서 확정한다.
- 게임 UI는 한국어이며 세력명에는 한자·장식 프레임(칭호)이 포함될 수 있다(사실: 참고 이미지 `演김부선`, `勇수정`, 5위 금색 프레임).
- 게임 업데이트로 UI 배치가 바뀌면 좌표·템플릿 갱신이 필요하다(운영 제약으로 수용).

## 가정과 미해결 질문

- 가정 A-01: 도구 실행 시점에 클라이언트는 로그인 완료 상태이며 메인 화면(더 보기 메뉴 열림 허용) 또는 공헌 랭킹 화면이다. 다른 화면이면 실패로 종료해도 된다.
- 가정 A-02: 랭킹 화면의 `본 서버` 드롭다운은 기본값(본 서버)이 선택되어 있다. 도구는 드롭다운을 조작하지 않는다.
- 가정 A-03 → 사실(P-01): 목록은 한 화면에 6행(행 간격 71px)을 표시하고 마우스 휠로 연속 스크롤된다. 노치당 이동량은 비일정(1노치 33px, 50노치 버스트 ≈815px)이므로 이동량은 프레임 매칭으로 측정한다([ADR-002](./work/20260928-contrib-ranking-capture/ADR-002-rank-assignment.md)). 목록은 600위에서 끝나며 끝에서는 휠이 무효다(P-01 버스트 52~60, 설계 A-07).
- 가정 A-04: 순위 번호는 1~3위 금색 메달 스타일, 4위 이후 흰색 숫자로 렌더링된다(참고 이미지 기준).
- 가정 A-05: 실행 중 랭킹이 갱신되어 순위가 바뀔 수 있다. 한 run은 스크롤 시점의 스냅샷이며 실행 중 변동에 따른 같은 세력명의 2회 등장은 허용한다(순위 기준 기록).

결정된 질문(2026-09-28 사용자 응답):

- Q-01 → 결정: 산출물은 **이미지 + 세력명·지역·동맹 텍스트**(템플릿 ID + 라벨 확정 방식 수용).
- Q-02 → 결정: **메인 화면에서 자동 이동**(이미 랭킹 화면이면 그대로 진행).
- Q-03 → 결정: **600위 도달 또는 목록 끝** 중 먼저 오는 조건에서 종료(`--max-rank` 기본 600).
- Q-04 → 결정: 설계 확정 전 **실기 프로토타입 P-01 수행**(승격 러너 사용).

프로토타입 기록:

- P-02(오프라인, 2026-09-28): 참고 이미지 6행에 Windows OCR(ko) 적용. 사실 — 세력명: 순한글 2건 정독, 한자 접두·장식 4건 오독(`演`→`寅`, 5위 장식 프레임 판독 불능). 지역: 4배 이진화 6/6. 동맹: 4배 이진화 5/6(`잠룡`→`잡룡`). 해석 — 세력명은 OCR 단독 불가, 지역·동맹은 폐쇄 집합이라 템플릿 판정이 적합하며 OCR은 라벨 제안용으로 충분.
- P-01(실기, 2026-09-28, 창 0x206be): 사실 — `더 보기`(1432,631) → `랭킹`(1235,585) → `공헌 랭킹` 탭(1378,138) 클릭으로 목표 화면 도달. 탭 클릭 직후 목록은 1위부터 표시. 행 테두리 y 268→339→410→482→553→624(간격 71.2). 휠 1노치 33px(2회 재현), 3노치 62px, 6노치 114px, 50노치 버스트 ≈11.4행. 버스트 52회로 600위 도달, 이후 8회 버스트는 화면 불변(목록 끝 = 600위, 끝 화면은 595~600위 정렬). 실측값은 [설계 DES-02](./design.md#des-02-상세)에 반영.
